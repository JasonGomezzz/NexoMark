Política de privacidad

Borrador v0.2 · Actualizado el 11 de octubre de 2026 · Sin fecha de vigencia. Consultar borrador anterior.

1. Responsables y contacto

NexoMark es un proyecto desarrollado por Jason Percy Jordan Gomez Mancha y Piero Fernando Huaytalla Otarola. El contacto para consultas de privacidad y solicitudes relativas a datos es nexomarkia@gmail.com.

2. Datos que maneja el proyecto

  • Cuenta: nombre, correo electrónico, rol, contraseña almacenada mediante un hash, fechas de registro y datos de sesión.
  • Campañas: datos del cliente o negocio, correo del cliente, instrucciones, textos, imágenes, versiones, aprobaciones, rechazos y comentarios.
  • Uso: créditos de generación, solicitudes de créditos, estados de procesamiento y registros de publicación y errores.
  • Funciones de voz: audio enviado para transcripción y texto resultante cuando el usuario utiliza esa función.
  • Redes conectadas: identificadores y nombres de las cuentas o páginas autorizadas, permisos y credenciales de acceso de las integraciones habilitadas. Las credenciales sociales se almacenan cifradas en el servidor; no se solicita la contraseña de la red social.

3. Para qué se utilizan

Para autenticar usuarios, aplicar permisos según su rol, crear y versionar campañas, generar contenido asistido por IA, gestionar la revisión por clientes, enviar notificaciones y atender solicitudes de publicación confirmadas por el usuario. Conectar una red no publica contenido automáticamente.

4. Quién puede recibir los datos

El marketero y el cliente asociado acceden al contenido necesario para gestionar y revisar sus campañas. Los administradores tienen acceso según sus funciones. Los datos necesarios para generar contenido y transcribir audio pueden enviarse a Google Gemini cuando se utilizan esas funciones.

Las redes sociales reciben los datos necesarios para autorizar conexiones y procesar las publicaciones solicitadas. Las notificaciones y el funcionamiento del servicio pueden involucrar proveedores de correo y alojamiento, según el despliegue. Sus políticas también regulan el tratamiento que realizan.

Antes de publicar: completar la lista de proveedores efectivamente usados, las ubicaciones de procesamiento y las condiciones de transferencia de datos aplicables al despliegue.

Para esta etapa se han identificado Google Gemini para las funciones de IA y Meta (Instagram/Facebook) y X para las conexiones habilitadas. TikTok se incluirá conforme a las funciones que efectivamente se implementen y autoricen. GitHub Pages es el alojamiento previsto para estas páginas informativas, no para la base de datos ni las campañas.

5. Estado de la integración con TikTok

TikTok está en preparación y pruebas; este borrador no afirma que su conexión o envío mediante API ya estén implementados. El flujo previsto solicitará información básica del perfil y permiso para enviar contenido aprobado para que el usuario termine la publicación en TikTok. Esta sección debe actualizarse conforme a la integración real antes de publicarse como política vigente.

6. Almacenamiento del navegador

La aplicación utiliza almacenamiento de sesión o almacenamiento local para conservar la sesión, el rol y datos de la cuenta, según la opción de recordar el inicio de sesión. Cerrar sesión elimina las credenciales de sesión de ese navegador. Estas páginas informativas no incluyen formularios, rastreadores ni scripts de analítica propios; GitHub Pages puede procesar datos técnicos de las visitas conforme a sus políticas.

7. Conservación y seguridad

El proyecto conserva cuentas, campañas e historial de operaciones en su base de datos. El código actual no establece una eliminación automática general por antigüedad. Se aplican controles de autenticación, permisos y cifrado de credenciales sociales; ninguna medida garantiza seguridad absoluta.

El criterio acordado para las pruebas de tesis es conservar solo los datos necesarios para esas pruebas y revisar su necesidad al concluir la tesis. Las evidencias académicas deberán utilizar datos anonimizados; no se establece una conservación indefinida de datos personales.

Pendiente de ejecución y verificación: definir cuándo finalizan las pruebas, inventariar datos y respaldos, documentar la eliminación o anonimización y comprobar la configuración del entorno público. Se propone una rotación de respaldos de 30 días, pero todavía no está implementada ni verificada y no constituye un plazo de eliminación garantizado.

8. Acceso, rectificación, cancelación y oposición

Puede contactar a nexomarkia@gmail.com para consultar los datos asociados a su cuenta, pedir correcciones o solicitar su eliminación. Se verificará su identidad de manera proporcional antes de atender una solicitud; no envíe contraseñas ni tokens. La atención será manual, conforme a las obligaciones aplicables y a las limitaciones que deban explicarse al solicitante.

También puede solicitar información sobre el tratamiento de sus datos o manifestar oposición a ese tratamiento. Indique el tipo de solicitud y el correo de su cuenta; no adjunte documentos sensibles salvo que se le explique por qué resultan necesarios. Los responsables deberán registrar la recepción, verificar la identidad proporcionalmente, evaluar los datos involucrados y comunicar la respuesta y sus motivos. Esta propuesta no sustituye los plazos ni requisitos legales aplicables.

Antes de publicar: asignar quién revisará el buzón y comprobar el procedimiento de registro y resolución de solicitudes, incluyendo campañas compartidas y copias de seguridad. No hay una función de borrado automático de cuenta implementada por este documento.

Desconectar una red desde Configuración elimina la credencial local de esa conexión; no elimina por sí mismo las campañas ni las publicaciones ya realizadas. También puede revocar la autorización desde la red social. Las publicaciones externas deben gestionarse en la plataforma correspondiente.

9. Precauciones y cambios

En las pruebas se priorizarán datos ficticios. Evite incluir datos sensibles o información de terceros que no tenga autorización para usar en las instrucciones, audios o campañas.

Las versiones de este documento conservarán su fecha e historial. Antes de modificar datos recopilados, finalidades o destinatarios, los responsables deberán evaluar las obligaciones de información y si corresponde obtener una nueva autorización. Los cambios relevantes se comunicarán a los usuarios afectados; actualizar el texto no autoriza por sí mismo un nuevo tratamiento ni reemplaza los requisitos de las redes sociales.
